# Middleware

> Intercept request, response and errors using H3 middleware.

> [!IMPORTANT]
> We recommend using composable utilities whenever possible. Global middleware can complicate application logic, making it less predictable and harder to understand.

Global middleware run on each request before route handler and act as wrappers to intercept request, response and errors.

:read-more{to="/guide/basics/lifecycle#3-dispatch-request" title="Request Lifecycle"}

You can register global middleware to [app instance](/guide/api/h3) using the [`H3.use`](/guide/api/h3#h3use).

**Example:** Register a global middleware that logs every request.

```js
app.use((event) => {
  console.log(event);
});
```

**Example:** Register a global middleware that matches certain requests.

```js
app.use(
  "/blog/**",
  (event, next) => {
    console.log("[alert] POST request on /blog paths!");
  },
  {
    method: "POST",
    // match: (event) => event.req.method === "POST",
  },
);
```

You can register middleware with `next` argument to intercept return values of next middleware and handler.

```js
app.use(async (event, next) => {
  const rawBody = await next();
  // [intercept response]
  return rawBody;
});
```

Example below, always responds with `Middleware 1`.

```js
app
  .use(() => "Middleware 1")
  .use(() => "Middleware 2")
  .get("/", "Hello");
```

> [!IMPORTANT]
> If middleware returns a value other than `undefined` or the result of `next()`, it immediately intercepts request handling and sends a response.

When adding routes, you can register middleware that only run with them.

```js
import { basicAuth } from "h3";

app.get(
  "/secret",
  (event) => {
    /* ... */
  },
  {
    middleware: [basicAuth({ password: "test" })],
  },
);
```

For convenience, H3 provides middleware factory functions `onRequest`, `onResponse`, and `onError`:

```js
import { onRequest, onResponse, onError } from "h3";

app.use(
  onRequest((event) => {
    console.log(`[${event.req.method}] ${event.url.pathname}`);
  }),
);

app.use(
  onResponse((response, event) => {
    console.log(`[${event.req.method}] ${event.url.pathname} ~>`, response.status);
  }),
);

app.use(
  onError((error, event) => {
    console.log(`[${event.req.method}] ${event.url.pathname} !! ${error.message}`);
  }),
);
```

## Reusing an authentication check

Put the authentication check in a function that takes an event. Middleware can call it before running the next handler, and an individual route handler can call it directly.

```ts [auth.ts]
import { defineMiddleware, requireBasicAuth, type HTTPEvent } from "h3";

const password = process.env.AUTH_PASSWORD;
if (!password) {
  throw new Error("Set AUTH_PASSWORD before starting the server.");
}

const credentials = { username: "admin", password };

export async function requireAuth(event: HTTPEvent) {
  await requireBasicAuth(event, credentials);
}

export const auth = defineMiddleware(async (event, next) => {
  await requireAuth(event);
  return next();
});
```

Register the wrapper with `app.use()`. This example limits it to routes under `/admin/`.

```ts [app.ts]
import { H3 } from "h3";
import { auth } from "./auth.ts";

export const app = new H3();

app.use("/admin/**", auth);
app.get("/admin/reports", () => "Private reports");
```

For an individual route, including a file-based route, await the same check inside the handler.

```ts [routes/account.ts]
import { defineHandler } from "h3";
import { requireAuth } from "../auth.ts";

export default defineHandler(async (event) => {
  await requireAuth(event);
  return "Private account";
});
```

[`requireBasicAuth()`](/utils/security#requirebasicauthevent-opts) throws an HTTP 401 error if the credentials are missing or invalid. In both examples, the protected handler runs only when the check succeeds.

In Nitro v3, you can also export `auth` as the default from a scanned [`middleware/` file](https://nitro.build/docs/routing#middleware). Nitro applies it to every route.
